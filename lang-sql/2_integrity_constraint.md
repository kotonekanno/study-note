## 概要

### 整合性制約（一貫性制約）とは

- `CREATE TABLE`文記述時に記述
- 登録されるデータが整合性のある状態に保たれるように制約を課す
- 制約を記述する場所によって、列制約とテーブル制約がある

### 整合性制約の例

- NOT NULL制約
- 一意性制約（UNIQUE KEY）
- キー制約（PRIMARY KEY）
- チェック制約（検査制約）
- 参照整合性制約（外部キー制約、FOREIGN KEY）

### 列制約とテーブル制約

1. **列制約**：各カラムのデータ型の後に記述
2. **テーブル制約**：テーブルの最後のカラム定義の後に記述し、テーブル全体に対して制約を課す

### 書式

```sql
CREATE TABLE <table_name> (
  column1 data_type1 <column-level_constraint1>,
  column2 data_type2 <column-level_constraint2>,
  ...
  <table-level_constraint> 
);
```

- 複数のカラムを指定する制約は、テーブル制約でないと定義できない
- NOT NULL制約は、列制約でないと定義できない

### 主なデータ型

1. 数値型
   - `int`：整数
   - `double`：小数点以下を含む数値
2. 文字列型
   - `char(n)`：固定長文字列、`n`は桁数（n文字未満の場合はスペースが埋め込まれる）
   - `varchar(n)`：可変長文字列、`n`は桁数
3. 日付型
   - `date`：年月日（`YYYY-MM-DD`）
   - `datetime`：年月日と時刻（`YYYY-MM-DD`）


## キー制約

- テーブルの主キーとなるカラムを`PRIMARY KEY`として指定できる制約
- 列制約の場合はテーブル内で1つだけ指定でき、複合キーはテーブル制約で記述する
- 一意であることを保証し、`NULL`を禁止する

#### 書式

1. 列制約

  ```sql
  column1 data_type1 PRIMARY KEY,
  ```

2. テーブル制約

  ```sql
  PRIMARY KEY(column1, ...)
  ```


## NOT NULL制約

- あるカラムに`NULL`値が入らないようにする制約
- 列制約でないと定義できない

#### 書式

```sql
column1 data_type1 NOT NULL,
```


## 一意性制約

- 重複したデータを禁止する制約
- キー制約（`PRIMARY KEY`）と異なり、
  - 複数の列に設定できる
  - `NULL`を禁止するわけではない
- 同じ値をその列（もしくは列の組み合わせ）に入力しようとすると、エラーが返される

#### 書式

1. 列制約
   
  ```sql
  column1 data_type1 UNIQUE,
  ```

2. テーブル制約

  ```sql
  UNIQUE(column1, ...)
  ```


## チェック制約

- カラムに条件を指定し、その条件を満たさないデータを禁止する制約
- カラムの値は、チェック制約で指定した条件に対して`TRUE`または`UNKNOWN`となる

#### 書式

1. 列制約

  ```sql
  column1 data_type1 CHECK(column1>=100),
  ```

2. テーブル制約

  ```sql
  CHECK(column1>0)
  ```


## 参照整合性制約（外部キー制約）

- テーブルとテーブルが外部キーによって参照関係にある場合の制約
- カラムAが別のカラムBを参照している場合、カラムAの定義の後に記述する

#### 書式

1. 列制約

  ```sql
  column1 data_type1 REFERENCES <table_name>(<column_name>),
  ```

2. テーブル制約

  ```sql
  FOREIGN KEY(column1) REFERENCES <table_name>(<column_name>)
  ```
