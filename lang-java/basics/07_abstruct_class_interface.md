## 抽象クラス

```java
abstract class クラス名 {
  abstract 戻り値型 メソッド名(引数);
}
```

- 未実装のメソッドを持てるクラス
- インスタンス化できない
- フィールド、実装済みメソッドを持てる
- 実装：`extends`（単一継承）

### 抽象メソッド

- 抽象クラスで宣言し、サブクラスで定義するメソッド
- 本体を持たず、実装を強制する
- `abstract`修飾子を付ける
- 小クラスで必ずオーバーライドする
- オーバーライドしない場合、子クラスも抽象クラスになる


## インターフェース

```java
interface インターフェース名 {
  戻り値型 メソッド名(引数);
}
```

- メソッド仕様（契約）のみを定義する型
- インスタンス化できない
- 構成要素
  - フィールド：`public`/`static`/`final`のみ
  - メソッド：抽象（例外あり）
- 実装：`implements`（複数可）

### implements構文

```java
class Bird extends Animal implements Flyable {
	@Override
	void speak() {
		System.out.println("tweet");
	}
	
	@Override
	public void fly() {
		System.out.println("fly");
	}
}
```

### アクセス修飾子

- インターフェースのメソッドは暗黙的に`public`
- 実装時に可視性を下げられない

### defaultメソッド

- インターフェースに実装を持たせるための仕組み
- 後方互換性のために導入
- 多用は非推奨

```java
interface A {
  default void foo() {
    // 実装
  }
}
```

### 型としての扱い

- インターフェースも型である
- ポリモーフィズムが成立する

```java
Flyable f = new Bird();
Animal a = new Bird();
```


## まとめ

#### 抽象クラス

- 継承：単一
- 状態（フィールド）：持てる
- 実装：可能
- 用途：共通基底

#### インターフェース

- 継承：複数
- 状態（フィールド）：原則持たない
- 実装：原則不可
- 用途：役割・能力
